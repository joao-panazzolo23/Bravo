# Contributing

First of all, thank you for considering contributing to this project! Any contribution, whether it's a bug fix, improvement, documentation update, or new feature, is welcome.

## Getting Started

Before making changes:

1. Read the project's README and familiarize yourself with its purpose and architecture.
2. Check existing issues and pull requests to avoid duplicating work.
3. Fork the repository and create a branch for your changes.

## Development Guidelines

- Follow the existing architecture and project structure.
- Keep changes focused and avoid unrelated modifications.
- Write clean, readable, and maintainable code.
- Follow existing naming conventions and coding standards.
- Avoid introducing unnecessary dependencies.
- Update documentation when your changes affect existing behavior or introduce new features.

## Testing

- Ensure the project builds successfully before submitting changes.
- Run the existing tests and add new tests when appropriate.
- Do not submit changes that knowingly break existing functionality.

## Submitting Changes

1. Create a branch for your contribution.
2. Make your changes and commit them with clear, descriptive messages.
3. Push your branch to your fork.
4. Open a Pull Request explaining:
   - What was changed.
   - Why the change was necessary.
   - How it was tested.
   - Any relevant issues related to the change.

## Bug Reports and Feature Requests

When opening an issue, provide as much relevant information as possible.

For bug reports, include steps to reproduce the problem, expected behavior, actual behavior, and relevant logs or screenshots.

For feature requests, explain the problem the feature aims to solve and, if possible, propose a solution.

## Code of Conduct

Be respectful, constructive, and open to different perspectives. Discussions should focus on improving the project, and all contributors are expected to maintain a welcoming and professional environment.

Thank you for helping improve this project!
